Agents work with the account's email, calendars, files, contacts and tasks, as the person who signs
in. Every request goes to Google live; nothing is copied. One sign-in covers Gmail, Calendar, Drive,
Docs, Sheets, Slides, Contacts and Tasks, and one connection holds them all. Gmail needs no app password, so it works for accounts
that can't make one.

## Before you start: a Google Cloud OAuth client

Hosted Personal Agent Proxy has its own Google client, so skip to
[Connect Google](#connect-google). A self-hosted Personal Agent Proxy needs one of its own, made in
a Google Cloud project you own. Google's console changes its layout from time to time; the names
below are the ones it shows today.

<Steps>

### Use the client from Google sign-in

If you set up [Google sign-in](/self-hosting/sign-in#google), use the same client. Otherwise, in
the [Google Cloud console](https://console.cloud.google.com/auth/clients), create an OAuth client
ID of the type **Web application**.

### Add the redirect URI

Under **Authorized redirect URIs**, add your Personal Agent Proxy's address followed by
`/api/connections/google/callback`, beside the one sign-in uses:

```text
https://proxy.example.com/api/connections/google/callback
```

Google takes redirect URIs on `https://` with a real domain, or on `http://localhost`. A LAN
address, such as `http://192.168.1.20` or `http://nas.lan`, won't register.

### Enable the APIs

Enable the Gmail API, Google Calendar API, Google Drive API, Google Sheets API, People API and
Google Tasks API in the client's project. [This link](https://console.cloud.google.com/flows/enableapi?apiid=gmail.googleapis.com,calendar-json.googleapis.com,drive.googleapis.com,sheets.googleapis.com,people.googleapis.com,tasks.googleapis.com)
asks for the project and enables all six. Documents and presentations are read and written through
Drive, so the Docs and Slides APIs aren't needed.

### Add the scopes

On the [Data Access](https://console.cloud.google.com/auth/scopes) page, **Add or remove scopes**
and add these, the ones a sign-in asks for:

```text
openid
https://www.googleapis.com/auth/userinfo.email
https://www.googleapis.com/auth/gmail.modify
https://www.googleapis.com/auth/gmail.send
https://www.googleapis.com/auth/calendar.events
https://www.googleapis.com/auth/calendar.calendarlist.readonly
https://www.googleapis.com/auth/calendar.events.freebusy
https://www.googleapis.com/auth/drive
https://www.googleapis.com/auth/contacts
https://www.googleapis.com/auth/contacts.other.readonly
https://www.googleapis.com/auth/tasks
```

### Choose the audience

On the [Audience](https://console.cloud.google.com/auth/audience) page, the user type and
publishing status decide who can connect and for how long:

- **A Google Workspace organization.** Choose the user type **Internal**. Everyone in the
  organization can connect, with every scope, without verification, a user limit or a warning.
- **A gmail.com account, or anyone outside one organization.** Choose the user type **External**,
  then **Publish app** so the status reads **In production**. Don't submit it for verification.
  Signing in shows "Google hasn't verified this app"; the person clicks **Advanced** and continues.
  That is expected on a self-hosted Personal Agent Proxy for a handful of people: Google allows 100
  such users per project, for the life of the project.

<Callout type="warning">
  Never leave the app in **Testing**. Google ends every sign-in, refresh token included, 7 days
  after consent, whatever the scopes, and the connection stops working until the person signs in
  again.
</Callout>

### Set the variables

If they aren't set already for sign-in:

```sh
GOOGLE_CLIENT_ID="…apps.googleusercontent.com"
GOOGLE_CLIENT_SECRET="…"
```

See [Environment variables](/self-hosting/environment).

</Steps>

Cloud projects made since May 2026 have Google's
[standard quotas](https://developers.google.com/workspace/tools-safety), far above what a few
people use, except Gmail's: each account gets 6,000 units a minute, and a page of 50 emails costs
about 1,000 of them, since each email in it is asked for on its own. An agent paging through more
than a few lists a minute is told the provider could not be reached, and can try again a minute
later.

## Connect Google

<Steps>

### Sign in with Google

Open **Connections**, then **Add connection**, and **Sign in with Google**. Connecting another
Google account makes another connection; signing in again with the same account gives its
connection new tokens and keeps its settings.

### Approve access

Google's consent screen lists every permission Personal Agent Proxy asks for, and the person can
untick some. An action whose permission was unticked is unavailable to every agent, marked "Not
allowed at sign-in", until the person signs in again from the connection's page. A connection made
before an action joined, such as Calendar, Contacts, who is free, other contacts or Tasks, has that
action marked the same way, until it is signed in again.

### Review the defaults

A new connection gives agents nothing, as a new mailbox gives agents no access to its email. The
connection's page shows the actions under Gmail, Calendar, Drive, Contacts and Tasks, each saying how many
are on, with **Enable all** above them, or **Disable all** once every one is on. Turn actions on or
off for every agent there, or only for one agent on the agent's page. A line above the permissions
says what that means for the account: what is ticked is what agents can read and do with it.

</Steps>

## What agents can do

Agents see Gmail as one list, the newest first, 50 to a page: all mail but Spam and Trash, as
Gmail's All Mail is, or one folder of it, the inbox, drafts, sent mail, the archive, Trash or Spam.
A search is Gmail's own, as in its search box, such as `from:sam has:attachment newer_than:7d`. You
can allow each action separately:

- **Read email** lists, opens and searches email. An email opens as its text, or its HTML as text
  where it has none, with its attachments listed. Each comes with its link in Gmail, in this
  account, for the agent to give you; a draft's opens it to be written. An attachment is read as
  text: a spreadsheet's tabs as CSV, a PDF's or a Word document's text, a forwarded email, or a
  text file as it is, the first 100,000 characters of it. Images and other files can't be read.
- **Mark read or unread**, **Star**, **Archive** and **Move email to Trash** act on messages in
  the inbox, and require Read email. Archived email stays in All Mail, and Gmail keeps Trash 30
  days before deleting it; nothing is deleted for good.
- **Write drafts** creates, edits and deletes drafts, and requires Read email. An edit keeps the
  draft's Cc, Bcc and thread, and its formatting while its text is unchanged; text written anew
  goes out as plain text. A draft with attachments isn't edited, since it would lose them.
  Received messages are never edited or deleted. A reply to an email is saved as a draft in its
  thread.
- **Send** sends a new email or a saved draft from the account's own address, and Gmail files it
  in Sent. It does not require Read email, so an agent can send without seeing the mailbox.
  Sending a reply needs Read email too, since it reads the email it answers.

A reply goes to whoever the email asks replies to go to, else its sender, or, for an email you
sent, to whom it went, under the email's subject with "Re:", in the email's thread in Gmail. A
reply to all also goes to everyone else the email went to and copies whom it copied, never the
account itself. An email opens with its Message-ID and its Gmail thread, and a reply says its own
id and thread, so an agent can check it landed in the conversation.

For Calendar, agents see the calendars in the account's list, the primary one first, and inside
each its events from now on, the soonest first, 50 to a page, each time a repeating event comes
round its own. A search is Google's, in titles, descriptions, locations and guests; one that begins
with a day, such as `2026-10-15 standup`, lists from that day on, earlier days too. Times read
with their offset, `2026-10-15T14:00:00+02:00`, and an all-day event as its first and last day.

- **Read events** lists, searches and opens events: their times, location, description, guests
  and their answers, the organizer, the video call and whether they repeat.
- **See when people are free** checks when the account and the people named, by their addresses,
  are busy, as Google's free/busy says, without what they are doing, and answers the times all of
  them are free, nights included. It doesn't require Read events. It checks from the time given
  to the time given, from now and for a week where they are left out; a time is written as an
  event's is, and a day alone is the whole day. Every time is answered on the primary calendar's
  clock. Someone whose calendar the account can't see, as is usual outside a Google Workspace
  organization, is said to be so rather than free, and the free times say they leave them out.
- **Create and edit events** makes events in a calendar the account can edit, the primary one
  unless another is named, and changes their title, times, location and description, and requires
  Read events. A time is written as `2026-10-15T14:00`, on the calendar's clock, or with an offset;
  a day alone makes an all-day event. Without an end an event lasts an hour, or the day, and a
  start moved without a new end keeps the event as long as it was. An event made or changed without
  guests tells no one.
- **Invite guests** adds guests to events and lets an agent change an event that has guests, and
  requires Create and edit events. Google emails the guests the invitation and every change, as
  Google Calendar does, so an agent with Create and edit events alone can't touch an event someone
  else is invited to.
- **Answer invitations** accepts or declines an event someone else invited the account to, or
  answers maybe, and requires Read events. Google tells the organizer.

Events are never deleted.

For Drive, Docs, Sheets and Slides:

- **Read files** browses and searches Drive and opens files. At the top are four places: My Drive,
  Shared with me, Shared drives and Recent. My Drive, folders and shared drives list their files
  folders first, Shared with me the last shared first, and Recent the files the account opened,
  in shared drives too, the last opened first, 50 to a page; trashed files are never listed. A
  search looks for words in file names and contents, anywhere in Drive, or among the files in the
  folder opened. A document opens as Markdown and a presentation as text, as Google exports them,
  up to Google's limit of 10 MB; past it, the content says the file is too large, and the file can
  still be renamed or moved to Trash. A spreadsheet opens into its tabs, and a tab into its rows,
  50 to a page, each row's values as `Header: value` lines, the headers from the tab's first row; a
  header used twice, or a column without one, goes by its column's letter, `Status (E)`. Other
  files, shortcuts included, open as their name, kind, owner, last change and link.
- **Create files** makes folders, documents and spreadsheets in My Drive, a folder or a shared
  drive, and adds rows to a spreadsheet's tabs, and requires Read files. A document is written as
  Markdown and a spreadsheet as CSV, and Google converts them as they are uploaded. A row is written
  as `Header: value` lines, under the headers of the tab's first row, and goes after the last row
  holding anything, from column A.
- **Edit files** renames files and a spreadsheet's tabs, replaces a document's content, and changes
  rows, and requires Read files. A document's content is replaced whole with the Markdown written,
  which drops its comments and suggestions, and only when it is written differently from how it
  read, so renaming a document leaves its content alone. Shared drives aren't renamed or trashed. A row changes only in the values written differently,
  so a formula in another of its cells stays. A presentation's and a spreadsheet's content are only
  read.
- **Move files to Trash** moves files and folders to Drive's Trash, where Drive keeps them 30 days
  before deleting them, and requires Read files. Nothing is deleted for good.

Agents can also read and write a range of a spreadsheet, in A1 notation with its tab, such as
`'Q1 Sales'!A1:F20`, given the spreadsheet's link or id, which covers tabs without a header row.
A range without a tab is in the first one. Reading needs Read files and answers the values as
Sheets shows them, as CSV, one row a line, 1000 rows at most.
Writing needs Edit files and takes CSV the same way, each value as if typed into its cell, so
`=SUM(B2:B9)` is a formula, and `""` empties a cell; it answers what the range holds afterwards.

For Contacts, agents see the account's contacts in Google Contacts, the most recently changed
first, 50 to a page. A search is Google's, matching the start of a name, email address, phone
number or company, and answers the first 30 it finds. Emails and phone numbers are comma-separated,
addresses one a line, and a birthday is `1990-04-12`, or `04-12` without the year.

- **Read contacts** lists, searches and opens contacts.
- **Read other contacts** lists, searches and opens the people Gmail keeps on its own under Other
  contacts: those the account emailed or was emailed by but never saved. Google keeps only their
  names, email addresses and phone numbers, and they are only read. With Add and edit contacts as
  well, an agent can save one, which copies it into Google Contacts as a contact of its own.
- **Add and edit contacts** adds contacts and changes their details, and requires Read contacts.
  An edit changes only the fields written differently, and an email, number or address still
  there keeps its label, such as work or home.

Contacts are never deleted.

For Tasks, agents see the account's task lists, and inside each its tasks in Google's own order,
subtasks and tasks assigned from Docs and Chat among them, 50 to a page: all of them, or only those
still to do or done. Tasks completed in Google Tasks, which it hides there, are listed as done. A due date is a day
alone, `2026-10-15`, as Google Tasks keeps no time of day.

- **Read tasks** lists and opens task lists and tasks: their title, notes, due day, list, whether
  they are done and when, the task a subtask is under, and the email a task was made from in
  Gmail.
- **Add and edit tasks** adds a task at the top of a list, the default list unless another is
  named, changes its title, notes and due day, moves it to another list when that list's name is
  written, and completes or reopens it, and requires Read tasks. A subtask moved to another list
  goes to its top level; Google doesn't move a repeating task to another list.

Tasks and task lists are never deleted, and lists are only read.

## Troubleshooting

- **`redirect_uri_mismatch`** on Google's page: the client doesn't have the exact redirect URI.
  Add your Personal Agent Proxy's address, exactly as `APP_URL` has it, followed by
  `/api/connections/google/callback`.
- **"Access blocked: … has not completed the Google verification process"**, or a message that the
  app is being tested: the app is in **Testing** and the account isn't a test user. Publish it, as
  under [Choose the audience](#choose-the-audience).
- **A connection stops working a week after connecting**, and agents are told "The provider turned
  this connection's sign-in down": the app was in **Testing**. Publish it, then sign in with Google
  again with the same account.
- **Connecting fails, and the api's log shows `invalid_client`** in Google's answer: the client
  secret doesn't belong to the client. Copy both again from the client's page into
  `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.
- **A run answers that an API "has not been used in project … before or it is disabled"**: enable
  that API from the link in the message, then try again a few minutes later.
- **`org_internal`**: the client's user type is **Internal**, and the account isn't in the Google
  Workspace organization that owns the project.
- **"This email already has an account"** is about signing in to Personal Agent Proxy with Google,
  not about connecting a Google account; see [Sign-in](/self-hosting/sign-in#google).

## Disconnecting

Deleting the connection revokes its tokens at Google. Google's grant is the account's for the
whole client, so while another connection is for the same Google account, in any organization on
the same Personal Agent Proxy, it is kept, and that connection goes on working. The person can also
revoke Personal Agent Proxy's access from their Google account, at
[Third-party apps & services](https://myaccount.google.com/permissions).
