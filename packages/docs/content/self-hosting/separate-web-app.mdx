---
title: Web app on its own host
description: Serve the web app from Vercel or another static host, apart from the api.
---

The image serves the web app and the api together on one address, which is the simplest way to
run Proxy. You can also host the web app on its own, as a static site on Vercel or a CDN, and run
the api apart from it. The two then need addresses on the same site, such as:

- `https://proxy.example.com` for the web app
- `https://api.proxy.example.com` for the api

Sign-in uses a cookie the browser only sends between the two when they share a parent domain.

<Steps>

### Run the api

Run the image as in [Get started](/self-hosting/get-started#without-docker-compose), with three
more variables, and `WEB_DIR` left empty so it serves the api alone:

```sh
APP_URL="https://proxy.example.com"
PROXY_API_PUBLIC_URL="https://api.proxy.example.com"
SESSION_COOKIE_DOMAIN=".proxy.example.com"
WEB_DIR=""
```

Google's redirect URI is then on the api's address:
`https://api.proxy.example.com/auth/google/callback`.

### Deploy the web app

On Vercel, import the repository with `packages/web` as the root directory; it builds with
`bun run build` into `dist`. Set the api's address, which is built into the app:

```sh
VITE_PROXY_API_URL="https://api.proxy.example.com"
```

Redeploy after changing it. Any other static host works too, as long as it answers every path
that is not a file with `index.html`, as `packages/web/vercel.json` does on Vercel.

</Steps>
