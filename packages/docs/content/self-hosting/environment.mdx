## Core

The variables marked **Required** are needed for Personal Agent Proxy to work. The optional Core
variables turn on quick actions on the home page and the built-in agent on the Chat page.

<EnvTable group="Core" />

A Chat agent can be set to run on the Claude Agent SDK, under each member's own Claude account,
which runs Claude Code as a subprocess for each turn: a few hundred megabytes of memory while the
turn lasts, on top of the server's own. `CLAUDE_AGENT_SDK_TURNS` is how many such turns one server
runs at once, one unless you raise it; a server with little memory to spare can turn the SDK off
with `CLAUDE_AGENT_SDK=off`: it is then not offered for an agent, and an agent that was set to it
runs on `OPENROUTER_KEY`.

## Connections

<EnvTable group="Connections" />

Agents' sandbox commands can use their connections through the `pap` command line tool
([Sandboxes](/connections/sandboxes)), which the server builds and installs in a sandbox itself:
nothing is downloaded. For that, `AUTH_SECRET` and `APP_URL` must be set, as the commands are
given a token signed with the one to call back to the other; the sandboxes must be able to reach
`APP_URL`; and the sandbox service's image must have Node 20 or newer, which `pap` runs on.

## Observability

The api writes its log to stdout, one JSON object per line, which `docker compose logs api` shows.
These ship it to a [Loki](https://grafana.com/oss/loki/) as well, and its metrics to a Prometheus
or any other store taking OTLP, as hosted Personal Agent Proxy does; a self-hosted server needs
none of them.
