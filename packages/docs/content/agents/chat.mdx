title: Chat with the built-in agent
description: Talk to an agent Personal Agent Proxy runs itself, with the same access settings and activity log as any agent you connect.
---

**Chat** in the sidebar is where you talk to agents Personal Agent Proxy runs itself. The
organization's agents are everyone's, like coworkers: anyone makes one with **+**, giving it a name
and a head, and whoever made it, or the organization's owner, renames or deletes it. All of them
act through one entry on the **Agent permissions** page, Chat, shared with everyone, as
Claude or ChatGPT are one entry each however many assistants run inside them: what the agents may
do with each shared connection is set there, once for all of them, and every call any of them makes
is in the activity log, by the task it was made for, which says which agent it was.

Your conversation with an agent is yours alone, as a direct message is: nobody else in the
organization sees it. In it, the agent acts as you, so it reaches what you see: the connections
shared with everyone, the ones you connected yourself and your own vault, beside the
organization's. On your own connections it follows their defaults, since a shared agent has no
settings of its own there. What it does in your conversation is in your activity log alone.

The agent you talk with does nothing to your accounts itself. It hands each piece of work to a
sub-agent: an agent with the same access, started on a brief, which does the work and answers.
The two keep talking: a sub-agent can ask the agent a question or say how far it has got while it
works, and the agent can send it more to do, or a follow-up to what it found, since the sub-agent
keeps everything it did and found. A sub-agent's work is one task in the activity log, titled as
the agent titled the sub-agent, with every call it made under it: finished, with what it answered
as the outcome, each time the sub-agent stops, and under way again when a message takes it up.

What it does differently from an agent you connect is where it runs: in Personal Agent Proxy, not
on another company's servers. The model is Claude Sonnet 5.5, reached through OpenRouter with a
host that neither keeps prompts nor trains on them, so a self-hosted Personal Agent Proxy needs an
`OPENROUTER_KEY`.

## How a conversation runs

Say what you want done. The agent answers, in a conversation and nothing else: the sub-agents it
starts, what they asked for and what they found are in the activity log, not on the page, each as
a task with the agent's head beside it. Sub-agents started together run side by side, and the agent
is free while they work: you can say more, and it answers; what a sub-agent says comes to it as a
message, and it tells you what matters of it, answers the sub-agent, or starts the next piece. A
call a sub-agent is not allowed is refused and logged as blocked, as it would be for any agent.
Everything keeps running after you leave the page, and the page shows the conversation as it is
when you come back.

A sub-agent can also wait: asked to check on something later, or to do something at a time, it
sleeps until then, and the page says until when. It wakes with its own log and nothing else, so it
says what it will do before it sleeps; a message from the agent wakes it earlier.

The agent can also come back to you later. Ask to be told at a time, and it sets an alert, which
wakes it then with what it noted, so it can tell you or do what you asked. Ask to be told when
something happens in your accounts, such as an email from a certain sender arriving, an issue
changing or a meeting being moved, and it sets a watch on the connections it may read: each new
email, issue or calendar event there that contains any of the words the agent noted comes to it,
with a link, for it to pass on. A watch matches words,
not meaning, so say what to look for the way it will be written. **Alerts** in the sidebar lists
what is set, with the agent that set each; delete one there, or ask the agent to cancel it.

A conversation can go on for as long as you like. Once it has grown long, the agent reads a
summary of the earlier part in place of it, and keeps the last turns as they were; the page shows
the whole conversation as before.

**Activity** under the input opens the activity log, where every sub-agent's task is listed with
the agent's head and name.

<Callout>
Chat is being tried out with some organizations first, so it is only offered to an organization
that has it turned on. On a self-hosted Personal Agent Proxy, turn it on for every organization in
its database:

```sql
UPDATE "Organization" SET experiments = array_append(experiments, 'harness')
WHERE NOT 'harness' = ANY(experiments);
```

</Callout>
