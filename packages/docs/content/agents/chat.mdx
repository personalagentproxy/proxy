**Chat** in the sidebar is a conversation with an agent Personal Agent Proxy runs itself. It is an
agent login like any other, named Personal Agent Proxy on the Agents page: what it may do with each
connection is set there, as for Claude or ChatGPT, and every call it makes is in the activity log,
by the conversation it was made for. It can use what you connected, and the vault as its memory.

What it does differently from an agent you connect is where it runs: in Personal Agent Proxy, not
on another company's servers. The model is Claude Sonnet 5.5, reached through OpenRouter with a
host that neither keeps prompts nor trains on them, so a self-hosted Personal Agent Proxy needs an
`OPENROUTER_KEY`.

## How a conversation runs

Say what you want done. The agent answers, or makes calls first: each shows as a card under its
message, with what it asked and, once it has it, what came back. A call it is not allowed is
refused and logged as blocked, as it would be for any agent. It keeps working after you leave the
page, and the page shows the conversation as it is when you come back.

It can also wait: asked to check on something later, or to do something at a time, it sleeps until
then, and the page says until when. It wakes with the conversation and nothing else, so it says
what it will do before it sleeps.

**Activity for this conversation** under the input opens the activity log narrowed to the
conversation's task.

<Callout>
Chat is being tried out with some organizations first, so it is only offered to an organization
that has it turned on. On a self-hosted Personal Agent Proxy, turn it on for every organization in
its database:

```sql
UPDATE "Organization" SET experiments = array_append(experiments, 'harness')
WHERE NOT 'harness' = ANY(experiments);
```

</Callout>
